# AlfaKit development

## When to use this skill

Use it when adding or changing panels, resources, forms, tables, actions, relation managers, infolists, widgets or custom pages in an app that uses `alfasix/alfakit`. Everything is defined in PHP; the React/Vue/Svelte renderer only displays the schema.

## Workflow

0. New app: `php artisan alfakit:setup` is the guided install (`--mode=panel|starter-kit|standalone`, `--users`, `--roles` (Shield), `--ai=openai,anthropic`, `--realtime`, `--plugins=activity-log,comments` (or `all`), `--bundle=saas|content|backoffice|support|ops` (comma-separated or `all`: a curated set of plugins registered with default navigation groups), `--brand-color="#2563eb"`, `--logo=images/logo.svg`, `--font=Inter`, `--demo`, `--migrate`, `--no-install` to never run composer/npm, `--no-interaction`); re-running skips finished steps; it defaults to a minimal install (every optional step no, no plugins). Add first-party plugins later with `php artisan alfakit:add comments activity-log [--panel=admin] [--migrate] [--no-install]` (composer require after a confirmation, `->plugin(...)` on the panel provider, migrations), list them with `alfakit:add --list` (`alfakit:add --list kanban` prints a plugin's highlights, its live-demo page from `config('alfakit.demo_url')` / `ALFAKIT_DEMO_URL` with a short tour, and the plugins it works with), and remove them with `alfakit:remove comments` (unregisters, composer remove; tables are kept). Its parts run on their own: `php artisan alfakit:users [--panel=] [--model=] [--roles] [--no-migrations] [--no-provider] [--force]` generates `App\Alfakit\Resources\UserResource` (invite with a signed link → `Users\Pages\AcceptInvitation`, `ImpersonateAction`, suspend/ban, require a new password → `Users\Pages\ChangePassword`, reset 2FA, last sign-in via `App\Listeners\RecordUserSignIn`, sessions with revoke on the database session driver) plus `App\Alfakit\Users\UserAccounts` helpers (`status()`, `suspend()`, `ban()`, `requirePasswordChange()`, `resetTwoFactor()`, `sessions()`, `revokeSessions()`, `invite(User::class, $data, $panel)`), the `EnsureAccountIsActive`/`RequirePasswordChange` auth middleware and a columns migration; `php artisan alfakit:ai-setup [--providers=openai,anthropic] [--default=] [--model=] [--check] [--no-test]` writes laravel/ai keys to `.env` (hidden prompt; without interaction from the process environment), publishes `config/ai.php`, sets the default provider/model and live-tests each key; `php artisan alfakit:realtime [--no-install]` installs Reverb (`install:broadcasting --reverb`, `reverb:install`), writes `REVERB_*`/`VITE_REVERB_*`, creates `resources/js/alfakit/echo.ts` (`window.Echo`, browser only) and enables `->realtime()` (real-time collaboration, see below).
1. Generate, don't hand-write: `php artisan make:alfakit-resource Post --generate` (`--view` adds a view page, `--simple` gives modal CRUD on one page, `--soft-deletes` adds trash support, `--model --migration --factory` create them, `--model-namespace=App\Domain\Blog\Models`). `--generate` reads the database columns. To choose columns, filters, infolist entries and relation managers: `php artisan alfakit:generate Post` (or `make:alfakit-resource --wizard`); in scripts pass every choice: `alfakit:generate Post --form=title,body,author_id --table=title,author_id --filters=author_id,is_published --infolist=title,body --relation-managers=comments --no-soft-deletes --no-interaction` (`none` selects nothing; omitted lists use the type-based defaults). Also `make:alfakit-relation-manager PostResource comments body --soft-deletes --view`, `make:alfakit-widget PostStats --resource=Post`, `make:alfakit-page ViewPostStats --resource=Post --type=ViewRecord|EditRecord|ManageRelatedRecords`, `make:alfakit-form|table Name --model=Post --generate`, `make:alfakit-rich-content-custom-block Hero`, `make:alfakit-theme acme --pm=pnpm`, `make:alfakit-issue`. Customise generated files by binding a subclass of `AlfaSix\Alfakit\Commands\Generators\ClassGenerator` (override `modify(string $stub, string $contents, array $replacements)`).
2. Edit the generated `form()`, `table()` and `infolist()`.
3. Register relation managers in `getRelations()`, widgets on the panel or a page.
4. Check the result in the browser and with a Pest HTTP test.
5. Coming from FilamentPHP: run `php artisan alfakit:migrate-from-filament --dry-run` first (writes `alfakit-migration-report.md` without changing files), then without `--dry-run` (`--adapter=react|vue|svelte`, `--keep-filament` to leave the composer packages). It rewrites PHP (`Filament\Forms\Form` → `Schema`, `toolbarActions()`/`BulkActionGroup` → `headerActions()`/`bulkActions()`, Heroicon → Lucide names, `Color::Amber` → hex, `$view` pages → reported), moves `app/Filament` → `app/Alfakit` and registers `App\Providers\Alfakit\*PanelProvider`. Every manual step is marked `// TODO(alfakit-migration): …` in the code (search for it); the report's summary gives the share converted automatically and the `php artisan alfakit:add …` command for the first-party plugins that replace Filament plugins (shield, media-library, tags, settings, comments, kanban, calendar, activity-log, tree, …). Livewire components get scaffolds to port: `app/Alfakit/Components/<Name>.php` (`<Name>::make()` in any schema) and `resources/js/alfakit/components/<Name>.(tsx|vue|svelte)` (auto-registered). Then: Blade views become frontend components, themes `make:alfakit-theme`, render hooks slots, Livewire tests `alfakit()->testPage()`.

## Forms

```php
use AlfaSix\Alfakit\Forms\Components\{Builder, CodeEditor, DatePicker, FileUpload, ModalTableSelect, MoneyInput, Repeater, RichEditor, Select, Slider, TextInput, Textarea, Toggle, ToggleButtons};
use AlfaSix\Alfakit\Schemas\Components\{Grid, Section, Tabs, Wizard};
use AlfaSix\Alfakit\Schemas\Components\Utilities\{Get, Set};

public static function form(Schema $schema): Schema
{
    return $schema->components([
        Section::make('Details')->schema([
            TextInput::make('title')->required()->maxLength(255)->live(onBlur: true)
                ->afterStateUpdated(fn (Set $set, ?string $state) => $set('slug', Str::slug((string) $state))),
            TextInput::make('slug')->required()->alphaDash()->unique(),
            Select::make('category_id')->relationship('category', 'name')->searchable()->preload(),
            Select::make('tags')->relationship('tags', 'name')->multiple(),
            RichEditor::make('body')->columnSpanFull(),
        ])->columns(2),
        Section::make('Pricing')->schema([
            Select::make('currency')->currencies()->default('USD')->live(),
            MoneyInput::make('price')->currency(fn (Get $get) => $get('currency'))->minorUnits(),
        ]),
        Repeater::make('items')->relationship()->schema([
            TextInput::make('name')->required(),
        ]),
    ]);
}
```

- Validation lives on the field (`required()`, `email()`, `numeric()`, `unique()`, `rule()`); it runs on the server.
- `$get('x')` / `$set('x', $v)` resolve from the component's container, as in Filament: inside a repeater item or builder block that is the item (`items.0`, `content.0.data`), for fields and layout components (`Text`, `Section`…) alike; each leading `../` goes up one level (`$get('../../currency')` reaches the root from an item); `isAbsolute: true` reads from the root. A dotted field (`make('settings.url')`) reads a sibling by its full name (`$get('settings.mode')`). Closure child schemas (`Section::make()->schema(fn (Get $get) => [...])`) are rebuilt whenever the state changes, so live updates see the browser's state.
- `unique()` ignores the bound record on edit forms (only when it checks the record's own table); `unique(ignoreRecord: false)` checks every row. `unique()`/`exists()` are tenant-scoped on tenant-owned tables. Laravel shortcuts: `alpha()`, `alphaDash()`, `alphaNum()`, `ascii()`, `string()`, `filled()`, `activeUrl()`, `hexColor()`, `ipv4()`, `ipv6()`, `macAddress()`, `enum(Status::class)`, `multipleOf(5)`, `notRegex()`, `gt/gte/lt/lte('other_field' or 10)`, `prohibitedIf()`, `prohibitedUnless()`, `prohibits()`, `requiredIfAccepted()`, `requiredWithAll()`, `requiredWithoutAll()`; field references resolve like `$get()` (siblings inside repeater items). `scopedUnique()` / `scopedExists(Post::class, 'id')` query through the Eloquent model (global scopes such as soft deletes apply, tenant-scoped) and take `modifyQueryUsing: fn (Builder $query) => $query->withoutGlobalScope(SoftDeletingScope::class)`; `scopedUnique()` has `ignorable:` / `ignoreRecord:` like `unique()`.
- `distinct()` on a field inside a Repeater or Builder block fails duplicates across items, with the error on each duplicate item path (`items.2.sku`).
- `Checkbox`/`Toggle`: `accepted()`, `declined()`. `CheckboxList::columns(3)` (alias `gridColumns()`) lays out the options, `->gridDirection('column')` fills column by column; `getOptionDescriptionFromRecordUsing(fn (Tag $record) => $record->summary)` for relationship options; `selectAllAction(fn (Action $action) => $action->label('…')->icon('…'))` / `deselectAllAction(...)` customise the bulk toggle links (label, icon, `hidden()`). `ToggleButtons::columns(3)->gridDirection('column')` lays buttons out in a grid.
- Select: `noOptionsMessage()`, `searchingMessage()`, `wrapOptionLabels(false)`; `allowHtml()` on `Select`/`CheckboxList` renders option labels as HTML, sanitised on the server. `prefixIconColor('danger')` / `suffixIconColor()` on `TextInput`, `Select` and the date pickers. Date pickers: `hoursStep()`, `minutesStep(15)`, `secondsStep()`, `weekStartsOnMonday()` / `weekStartsOnSunday()` (default: the panel locale's first day), `defaultFocusedDate(now()->addMonth())`. `Textarea::disableGrammarly()`.
- Content slots on fields and entries: `aboveLabel()`, `beforeLabel()`, `afterLabel()` (end-aligned next to the hint), `belowLabel()`, `aboveContent()`, `beforeContent()`, `afterContent()`, `belowContent()`, and on fields `aboveErrorMessage()` / `belowErrorMessage()` (shown with an error). Each takes a string, `HtmlString`, schema component (`Text`, `Icon`…), `Action`/`ActionGroup`, an array of these or a closure, plus an optional `Alignment::Start|End|Between`: `TextInput::make('slug')->belowContent(['Used in the URL.', Action::make('generate')->action(fn (Get $get, Set $set) => $set('slug', Str::slug($get('title'))))])`. Slot actions run like field actions. `extraFieldWrapperAttributes([...])` / `extraEntryWrapperAttributes([...])` set wrapper attributes (merged with `extraAttributes()`).
- `FusedGroup::make([Select::make('code')->placeholder('Code'), TextInput::make('phone')->placeholder('Number')->columnSpan(2)])->label('Phone')->columns(3)` (`AlfaSix\Alfakit\Schemas\Components\FusedGroup`) fuses fields into one bordered control; child labels become screen-reader text, child helper texts are hidden, errors are listed below.
- `saved(false)`: validated and kept in the form state, but left out of `getState()` and its relationship isn't saved (password confirmations); `disabled()->saved()` saves a disabled field's server value. `validatedWhenNotDehydrated(false)` skips the rules of non-dehydrated fields. `allowHtmlValidationMessages()` renders the field's messages as HTML (don't use `:input` in them).
- Private files: `FileUpload::make('doc')->disk('s3')->visibility('private')` serves previews/links via `temporaryUrl()` (`config('alfakit.temporary_file_url_expiry_minutes')`, 30, rounded up to the end of the hour; `->temporaryUrlExpiry(60)` per FileUpload/ImageColumn/ImageEntry/RichEditor; the disk must support it, e.g. S3 or a `local` disk with `serve`); `RichEditor::make('body')->fileAttachmentsVisibility('private')` saves plain URLs and signs them when the form is filled; sign for display with `RichContentRenderer::make($content)->fileAttachments('s3', 'posts', 'private')` (or `$post->renderRichContent('content')` with the model config). Visibility defaults to the disk's `visibility` config. `FileUpload::make('attachments')->multiple()->storeFileNamesIn('attachment_file_names')` saves original names to that sibling attribute (`[path => name]`, cast it to `array`; a single field stores the name) and shows them.
- `relationship()` on Select, Repeater and CheckboxList saves the relation for you.
- Polymorphic relations: `MorphToSelect::make('commentable')->types([MorphToSelect\Type::make(Post::class)->titleAttribute('title'), MorphToSelect\Type::make(Product::class)->getOptionLabelFromRecordUsing(fn (Product $record) => $record->name)->modifyOptionsQueryUsing(fn (Builder $query) => $query->where('active', true))])->searchable()->preload()->required()` (`AlfaSix\Alfakit\Forms\Components\MorphToSelect`). It is a fieldset with a type `Select` (`typeSelectToggleButtons()` for buttons) and a key `Select`, filling and saving the record's `commentable_type` / `commentable_id` (make them fillable); the type is the morph class (morph map alias). The type must be one of `types()`, the key must exist in that type's tenant-scoped query. `modifyTypeSelectUsing()`, `modifyKeySelectUsing()`, `Type::label()`, `Type::searchColumns()`, `contained(false)`, `native()`, `optionsLimit()`.
- Repeater relationships: `Repeater::make('products')->relationship()` also takes a BelongsToMany (items are pivot rows: the item field named after the related pivot key, e.g. `Select::make('product_id')`, picks the record and is required + distinct; other item fields are pivot columns, attached/updated/detached), or use a HasMany to a pivot model (`orderProducts`). `relationship(modifyQueryUsing: fn (Builder $query) => ..., modifyRecordsUsing: fn (Collection $records) => ...)` limits the managed records (others are never touched); `afterCreate(fn (array $data, Model $record))`, `afterUpdate(...)`, `afterDelete(fn (Model $record))`; `mutateRelationshipDataBeforeCreateUsing()` / `...BeforeSaveUsing()` returning null skip the item.
- Inside a `relationship()` Repeater, item fields are scoped to the related model: `unique()`/`exists()` check its table, `$record` is the item's record, and rule references like `requiredIf('type', ...)` or `same('other')` mean sibling fields of the same item. `addable(false)`, `deletable(false)` and `reorderable(false)` are enforced on the server.
- Block content: `Builder::make('content')->blocks([Block::make('heading')->icon('heading')->schema([TextInput::make('text')->required()]), Block::make('image')->maxItems(1)->schema([...])])->blockPickerColumns(2)->collapsible()->cloneable()` (`AlfaSix\Alfakit\Forms\Components\Builder\Block`). The state is a list of `['type' => 'heading', 'data' => [...]]`; store it in a JSON column with an `array` cast. Block types, block `maxItems()` and every block field are validated on the server; `Block::label(fn (?array $state) => ...)` labels items after their data. `Block::summary(fn (array $state): ?string => $state['text'] ?? null)` adds a plain-text line after the label (HTML stripped, 160 characters; also gets `$index`), and `Builder::blockActionsMenu()` moves the item actions (move, duplicate, extra actions, delete) into one **More** menu per item header. The block picker flips above the add button when there is no room below and stays clear of the sticky top bar. Picker headings: `->blocks(['Content' => [Block::make('heading'), ...], 'Media' => [...]])` or `Block::make('x')->group('Media')` (ungrouped blocks first). No `relationship()`/`simple()` on Builder.
- `ToggleButtons::make('status')->options([...])->colors([...])->icons([...])->inline()` (or `->grouped()`, `->multiple()`, `->boolean()`, `->columns(3)`); `Slider::make('price')->range(minValue: 0, maxValue: 1000)->step(10)->default([200, 800])->tooltips()->pips()` (an array default makes a range; `minDifference()`/`maxDifference()`; `rangePadding([10, 20])`, `rtl()`, `nonLinearPoints(['20%' => 50, '50%' => [75, 5]])`, `pips(PipsMode::Count)->pipsValues(5)` with `AlfaSix\Alfakit\Forms\Components\Slider\Enums\PipsMode` (`Steps`, `Positions`, `Count`, `Values`), `steppedPips()`, `pipsFilter(fn (int|float $value): int => …)` run in PHP (1 large label, 2 small, 0 tick, -1 hidden), `behavior([Behavior::Tap, Behavior::Drag, Behavior::Fixed])` from `…\Slider\Enums\Behavior`, `behavior(null)` for none); `CodeEditor::make('snippet')->language(Language::Php)` (`AlfaSix\Alfakit\Forms\Components\CodeEditor\Enums\Language`; `wrap()`, `lineNumbers(false)`, `maxHeight()`).
- `ModalTableSelect::make('author_id')->relationship('author', 'name')->tableConfiguration(UserResource::class)` picks records from a table in a modal (search, filters, sort, pagination). `tableConfiguration()` takes a resource class, a class with `static configure(Table $table): Table`, or a closure receiving `$table`; add `->multiple()->maxItems(5)` for BelongsToMany. Without a relationship, the configuration sets `query()` and `recordTitleAttribute()` names the label. The list is tenant scoped and submitted keys are validated against it. `->selectAction(fn (Action $action) => $action->label('Pick')->icon('search')->modalHeading('Search')->modalDescription('…')->modalSubmitActionLabel('Use')->modalWidth(Width::FiveExtraLarge))` customises the button and modal; `->tableArguments(fn (Get $get): array => ['category_id' => $get('category_id')])` passes form values to a closure configuration as `$arguments` (`fn (Table $table, array $arguments) => …`; classes read `$table->getContext()->getTableArguments()`), display only.
- `->live(debounce: 500)` takes milliseconds or a duration string (`'750ms'`, `'1s'`). Without it, typed fields debounce 150 ms and choice fields (select, toggle, checkbox, radio, date pickers, uploads) refresh at once; custom fields override `getDefaultLiveDebounce(): int`. `$set('region', null, shouldCallUpdatedHooks: true)` also runs the target's `afterStateUpdated()`.
- `afterStateUpdated(fn ($state, $old) => ...)` receives the previous value as `$old`. Live refreshes answer with only the changed components and state keys; nothing to configure. To limit further: `->partiallyRenderComponentsAfterStateUpdated(['total'])` (sibling names, keys or state paths), `->partiallyRenderAfterStateUpdated()` (the field only), `->skipRenderAfterStateUpdated()` (no components; `$set()` state still arrives; without `afterStateUpdated()` no request at all).
- Field actions: `TextInput::make('slug')->suffixAction(Action::make('generate')->icon('sparkles')->iconButton()->action(fn (Get $get, Set $set) => $set('slug', Str::slug($get('title')))))`, also `prefixAction(s)()` and `hintAction(s)()` on fields and infolist entries. In their closures `$component` is the field, `$state` its state, `$get`/`$set` act on the field's form (the change reaches the browser), `$data` is the action's own modal data. Actions of hidden or disabled fields can't run.
- Select option modals: `Select::make('author_id')->relationship('author', 'name')->createOptionForm([TextInput::make('name')->required()])->editOptionForm([TextInput::make('name')->required()])` creates (policy `create`) or updates (policy `update`) the related record and selects it; `createOptionUsing(fn (array $data) => $key)` / `updateOptionUsing(fn (array $data, Model $record) => ...)` for custom saving (required without a relationship), `createOptionAction(fn (Action $action) => $action->modalWidth('lg'))`, `createOptionModalHeading()`.
- One related record in a layout component: `Section::make('SEO')->relationship('seo')->schema([TextInput::make('meta_title')])` (also `Group`, `Fieldset`; HasOne, MorphOne, BelongsTo, MorphTo with `relationship('attachable', relatedModel: Image::class)` to create one). State nests under the name (`seo.meta_title`), the data stays out of the owner's attributes and is saved after the owner; `relationship('address', condition: fn (array $state) => filled($state['street'] ?? null))` skips (and deletes or dissociates) when false; `mutateRelationshipDataBeforeFillUsing()`/`...BeforeCreateUsing()`/`...BeforeSaveUsing()`. Not inside repeater items.
- Long Repeaters and Builders render only the visible items above 50 (`virtualize(false)` turns it off, `virtualizeThreshold(200)` moves the threshold, `virtualizeEstimateSize(96)` tunes the pre-measurement row height in px); all three renderers keep keyboard navigation, drag reorder, collapse state and scroll the first errored item into view on validation. A multi-column `grid()` repeater is windowed by whole rows (the renderer counts the rendered grid's columns).
- Table repeaters: `Repeater::make('lines')->table([TableColumn::make('Product')->width('50%'), TableColumn::make('Qty')->alignment(Alignment::End)])->schema([...])` (`AlfaSix\Alfakit\Forms\Components\Repeater\TableColumn`; columns follow the schema order; `hiddenHeaderLabel()`, `markAsRequired()`, `wrapHeader()`). `RepeatableEntry::make('lines')->table([...])` uses `AlfaSix\Alfakit\Infolists\Components\RepeatableEntry\TableColumn`.
- Repeater / Builder item actions are Actions: `->deleteAction(fn (Action $action) => $action->requiresConfirmation())`, also `addAction()`, `cloneAction()`, `reorderAction()`, `moveUpAction()`, `moveDownAction()`, `collapseAction()`, `expandAction()`, `collapseAllAction()`, `expandAllAction()`; `->extraItemActions([Action::make('email')->action(fn (array $arguments, Repeater $component) => $component->getItemState($arguments['item']))])`. `$arguments['item']` is the item's position (`'0'`); reorder gets `$arguments['items']`, the Builder's add `$arguments['block']`. Restyled-only actions run in the browser; ones with a modal/handler/hooks run on the server. Layout: `reorderableWithButtons(false)`, `reorderableWithDragAndDrop(false)`, `addActionAlignment(Alignment::End)`, `itemNumbers()`. `KeyValue` has `addAction()`, `deleteAction()`, `reorderAction()`.
- `Select::make('product_id')->disableOptionsWhenSelectedInSiblingRepeaterItems()` inside a repeater item disables options other items picked (adds `distinct()` + `live()`).
- Builder previews: `->blockPreviews(areInteractive: false)` with `Block::make('hero')->preview('blocks.hero')` (Blade view, item data as variables; or a closure returning HTML) or `->previewComponent('hero')` (renderer registry key `builder-preview:hero`, props `data`, `block`, `index`). `blockPickerWidth(Width::Large)`. Tests: `Repeater::fake()` / `Builder::fake()` return an undo closure (keys are positional anyway).
- RichEditor: `->json()` stores a Tiptap document (cast to `array`); `->customBlocks([HeroBlock::class])` with `class HeroBlock extends RichContentCustomBlock` (`configureEditorAction(Action $action): Action` adds `->schema([...])`, `toPreviewHtml(array $config)`, `toHtml(array $config, array $data)`; escape config values); `->mentions([MentionProvider::make('@')->getSearchResultsUsing(fn (string $search): array => User::where('name', 'like', "%{$search}%")->limit(10)->pluck('name', 'id')->all())])` or `->items([...])`; `->mergeTags(['name', 'today' => 'Today'])`. Display with `RichContentRenderer::make($content)->mergeTags(['name' => $user->name])->customBlocks([HeroBlock::class])->toHtml()` (namespace `AlfaSix\Alfakit\Forms\Components\RichEditor\`); stored HTML is sanitised first. In an infolist return the renderer itself: `TextEntry::make('content')->html()->state(fn (Post $record) => RichContentRenderer::make($record->content))`.
- RichEditor toolbar extras (opt in via `->toolbarButtons([...])`; the default toolbar is unchanged): `subscript`, `superscript`, `code`, `highlight`, `textColor` (palette from `->textColors(['#dc2626' => 'Red', ...RichEditor::getDefaultTextColors()])`, `->customTextColors()` adds a free picker), `alignStart`/`alignCenter`/`alignEnd`/`alignJustify` (logical, stored as `style="text-align: …"`), `table` (plus `tableAddColumnBefore|After`, `tableDeleteColumn`, `tableAddRowBefore|After`, `tableDeleteRow`, `tableMergeCells`, `tableSplitCell`, `tableToggleHeaderRow|Cell`, `tableDelete`, shown in a row while the cursor is in a table), `details`, `h1`–`h6`, `paragraph`, `clearFormatting`; `->linkProtocols(['https', 'mailto'])` limits link schemes (editor, save and `RichContentRenderer::linkProtocols()`). Images pointing at another file on the attachments disk are dropped on save unless the stored content referenced it (`->preventFileAttachmentTampering(bool, allowFilePathUsing: fn (string $file): bool => ...)`, on by default). Custom storage: `->fileAttachmentProvider(new MyProvider)` implementing `RichEditor\FileAttachmentProviders\Contracts\FileAttachmentProvider` (`saveUploadedFileAttachment(TemporaryUpload $file): ?string` returns the URL to store, `getFileAttachmentUrl()`, `getDefaultFileAttachmentVisibility()`, `isExistingRecordRequiredToSaveNewFileAttachments()`, `cleanUpFileAttachments(array $exceptIds)`), also on `registerRichContent()` or from a plugin implementing `Plugins\Contracts\HasFileAttachmentProvider`; default `DiskFileAttachmentProvider`. `->fileAttachmentsAcceptedFileTypes(['image/png', 'image/jpeg'])` and `->fileAttachmentsMaxSize(2048)` (KB) are checked in the browser and again on save (validation error); SVG is never accepted. MarkdownEditor's `table` button stores GitHub tables. The sanitiser keeps only `color`, `background-color` and `text-align` in `style`.
- RichEditor layout: `ToolbarButtonGroup::make('Heading', ['h1', 'h2', 'h3'])->icon('heading')->textualButtons()` inside `toolbarButtons([...])` is a dropdown; `->floatingToolbars(['paragraph' => ['bold', 'link'], 'heading' => [...], 'table' => [...]])` shows buttons above the selection (text nodes while text is selected; `table`/`image`/`customBlock`… while inside or selected; a `table` one replaces the table row); `->stickyToolbar()`, `->stickyPanels()`, `->stickyOffset('4rem')`; `->resizableImages()` stores `<img width="320">`. Grids get a default floating toolbar (`gridAddColumnBefore`, `gridAddColumnAfter`, `gridDeleteColumn`, `gridDelete`). Custom block previews skip prose styles unless the block's `shouldApplyProseStylingToPreview(array $config): bool` returns true. Mentions render the provider's `getLabelsUsing()` label (else the stored one). The `customBlocks`/`mergeTags` buttons open side panels: `->customBlocks(['Marketing' => [HeroBlock::class], DividerBlock::class])` groups blocks, plus `->searchableCustomBlocks()`, `->customBlocksGrid()`, `->minimalCustomBlockControls()`, `->activePanel('customBlocks'|'mergeTags')`; `->mergeTags(['name'])->mergeTagLabels(['name' => 'Full name'])`.
- Rich content models: `class Post extends Model implements HasRichContent { use InteractsWithRichContent; public function setUpRichContent(): void { $this->registerRichContent('content')->fileAttachmentsDisk('s3')->fileAttachmentsVisibility('private')->customBlocks([...])->mergeTags(['name' => fn () => auth()->user()?->name])->mergeTagLabels([...])->plugins([...]); } }` (`RichEditor\Models\Contracts\HasRichContent`, `RichEditor\Models\Concerns\InteractsWithRichContent`). `RichEditor::make('content')` uses it for unset settings; `$post->renderRichContent('content')` renders (sanitised, blocks, merge tag values, private images signed).

{
    return $table
        ->columns([
            TextColumn::make('title')->searchable()->sortable()->limit(50),
            TextColumn::make('category.name'),                         // label "Category"

        ->recordActions([ViewAction::make(), EditAction::make(), DeleteAction::make()])

}

- Selection: `->maxSelectableRecords(50)`, `->selectGroupsOnly()` (while grouped), both enforced on the server (422). `BulkAction::make('x')->fetchSelectedRecords(false)` gives `Illuminate\Support\Collection $records` of keys (`DeleteBulkAction`, `ForceDeleteBulkAction`, `RestoreBulkAction`, `DetachBulkAction` then act by query in chunks of 500, without model events; add `->authorizeIndividualRecords(null)` to skip loading records for the per-record policy check); inside the action `$action->reportBulkProcessingFailure('key', message: fn (int $failureCount, int $totalCount): string => ...)` and `->failureNotificationTitle(fn (int $successCount, int $failureCount, int $totalCount): string => ...)` report partial failures. - `SelectColumn::make('author_id')->native(false)->optionsRelationship('author', 'name', ignoreRecord: false, modifyQueryUsing: fn (Builder $query) => ...)->searchableOptions(['name', 'email'])->optionsLimit(20)->allowOptionsHtml()` (labels sanitised; `preloadOptions()`, `getOptionsSearchResultsUsing()`, `getOptionLabelUsing()`, `getOptionLabelFromRecordUsing()`; combobox messages `searchPrompt()`, `loadingMessage()`, `searchingMessage()`, `noSearchResultsMessage()`, `noOptionsMessage()`). `ImageColumn::make('cover')->alt(fn (Post $record) => $record->title)`.
- Long pages: tables with more than 50 rows render only the visible rows (`->virtualize(false)`, `->virtualizeThreshold(200)`, `->virtualizeEstimateSize(64)`); the markup keeps `aria-rowcount` / `aria-rowindex`. Content layouts and `contentGrid()` cards are windowed by whole rows too.
- Non-Eloquent data: `->records(fn (?string $search, ?string $sortColumn, ?string $sortDirection, int $page, int|string $recordsPerPage, array $filters) => [...])`. Arrays and collections are searched, sorted and paged by the table; return a paginator to do it yourself. Rows carry record actions, bulk selection and inline edits: the row's key is posted back and resolved from the closure (or `->resolveRecordUsing(fn (string $key): ?array => ...)`); closures take `array $record` (a `Model $record` closure gets null), bulk actions get a `Collection` of arrays, and inline-editable columns need `updateStateUsing()` (400 without it). A closure asking for `$filters` filters the rows itself; otherwise the table applies the filters to the rows: `SelectFilter`/`TernaryFilter` compare their attribute, and `query(fn (Collection $records, array $data) => $records->where(...))` gets the rows (keep the keys; a `Builder`-typed closure is skipped).
- `ViewColumn::make('status')->view('StatusSwitcher')->viewData(fn ($record) => [...])` and `ViewEntry` render a registered frontend component.

## Actions

- A modal `CreateAction` (with `->form()`) shows "Create & create another", which saves, keeps the modal open and resets the form; `->createAnother(false)` hides it, `->preserveFormDataWhenCreatingAnother(['category_id'])` (or no argument for every field, or `fn (array $data): array => Arr::only($data, ['category_id'])`) keeps values for the next record; `->createAnotherAction(fn (Action $action): Action => $action->label('Save and add another')->icon('plus'))` customises the button (return `false` to remove it).

- Prebuilt: `CreateAction`, `EditAction`, `ViewAction`, `DeleteAction`, `RestoreAction`, `ForceDeleteAction`, `ReplicateAction`, plus `AttachAction`, `DetachAction`, `AssociateAction` and `DissociateAction` in relation managers, and the `*BulkAction` versions.

- Undo: `DeleteAction::make()->undoable()` / `DeleteBulkAction::make()->undoable()` restore soft-deleted records from an "Undo" button (with countdown, Ctrl/Cmd+Z) in the success toast and drop the confirmation modal (`->skipConfirmationWhenUndoable(false)` keeps it); `EditAction::make()->undoable(seconds: 10)` and `protected static bool $isSaveUndoable = true;` on an `EditRecord` page put back the changed attributes (refused if the record changed since; `undoTrackedAttributes([...])`). The undo token is single-use, short-lived and bound to user/panel/tenant; the policy is re-checked (`POST /_alfakit/actions/undo` with `{undo}`).
- An action with `->url(...)` is a link and is never executed.
- Modal forms with a record fill from its attributes; `->mutateRecordDataUsing(fn (array $data, Model $record): array => [...$data, 'title' => ucfirst($data['title'])])` changes them first (skipped when `fillForm()` is set). - Page header actions go in `getHeaderActions()` on the page class.
- Resource page hooks (protected methods on `CreateRecord` / `EditRecord` / `ViewRecord` subclasses): `beforeFill()` / `afterFill()` (once, when the page loads), `beforeValidate()` / `afterValidate()` (on submit), `beforeCreate(array $data)` / `afterCreate()`, `beforeSave(array $data)` / `afterSave()`, plus `mutateFormDataBeforeFill/Create/Save(array $data): array`. - Guest access (public pages in a panel): `$panel->guestAccess()` (or `->guestAccess(fn (?Team $tenant): bool => $tenant === null || $tenant->is_public)` on tenancy panels), then `protected static bool $isGuestAccessible = true;` on each page, or on a resource for all its pages. - Import/export: generate `php artisan make:alfakit-importer Product --generate` / `make:alfakit-exporter Product --generate` (aliases `alfakit:make-importer`, `alfakit:make-exporter`), then `$table->headerActions([ImportAction::make()->importer(ProductImporter::class), ExportAction::make()->exporter(ProductExporter::class)])` and `->bulkActions([ExportBulkAction::make()->exporter(ProductExporter::class)])`. ## Inside a Laravel starter kit

- `php artisan alfakit:install --starter-kit` (or `alfakit:setup`, which picks it when `resources/js/layouts/app-layout.tsx`, `AppLayout.vue` or `AppLayout.svelte` exists) wires a panel into an app made from Laravel's React, Vue or Svelte starter kit. It writes `resources/js/pages/Alfakit/Page.(tsx|vue|svelte)`, `resources/js/components/alfakit-nav.tsx` (`AlfakitNav.vue`, `AlfakitNav.svelte`, built from the app's `@/components/ui/sidebar`), adds `<AlfakitNav />` after `<NavMain />` in the app sidebar (block marked `alfakit:nav`), adds `<AlfakitSearch />` and `<AlfakitNotifications />` to `app-sidebar-header` and `app-header` (`AppSidebarHeader`, `AppHeader`; block marked `alfakit:header`, skip with `--no-header-widgets`), imports `@alfakit/<kit>/standalone.css` in `resources/css/app.css`, and creates a panel provider with `->starterKit()`. The entry `resources/js/app.*` is not changed: Inertia resolves `Alfakit/Page` from `resources/js/pages`. Don't create `resources/js/alfakit/app.*` in this mode.
- `$panel->starterKit(rootView: 'app', loginRoute: 'login')` (alias `->embedded()`): the host's root view and Fortify login (AlfaKit's login, registration, password reset and profile pages are off), pages inside the host `AppLayout`, no AlfaKit theme or appearance on the document (the host's shadcn tokens and dark mode apply). Keep `->middleware(['web'])`; add `->authMiddleware(['verified'])` to match the kit's dashboard. The navigation is shared with every Inertia page as the `alfakitNavigation` prop (the panel's own `alfakit.navigation` is empty; tenancy panels share empty `groups` outside a tenant), each entry with `widgets` (`endpoint`, `search`, `notifications`, `tenancy`) for the header components. `->multiFactorAuthentication()` is ignored while the host signs users in (use the kit's Fortify two-factor settings); it applies again only with `->login()`.
- Frontend: the page file exports `createStarterKitPage({ layout: AppLayout, components: { 'map-picker': MapPicker } })` (`@alfakit/react`, `@alfakit/vue`); Svelte uses `export const layout = createStarterKitLayout({ layout: AppLayout })` in `<script module>` and renders `<AlfakitPage />`. Custom components go in that `components` option. The sidebar reads `useAlfakitNavigation(panelId?)` (`groups[].items[]` with `title`, `href`, `icon`, `isActive`, `badge`, `badgeTooltip`, `openInNewTab`, `children`; render icons with `<Icon name={item.icon} />`). AlfaKit's sidebar, top bar and user menu are not rendered in this mode; its command palette/global search, database notifications bell and tenant switcher go in the host header as `<AlfakitSearch />`, `<AlfakitNotifications />` and `<AlfakitTenantSwitcher />` (same names in `@alfakit/react`, `@alfakit/vue`, `@alfakit/svelte`; optional `panel` prop). They work on every host page, render nothing for guests or without `globalSearch()`/commands, `databaseNotifications()` or `tenant()`, and lazy-load their code and the panel data (`GET /{path}/_alfakit/starter-kit`). The header palette lists search results, navigation, create links and recent records (no panel commands, page actions or theme items); the key bindings (`globalSearchKeyBindings()`, ⌘K) are registered once. The same exports are available from `@alfakit/<kit>/starter-kit` (areas also have `/kanban`, `/cms`, `/translation-manager`, `/ai`, `/tree` and `/realtime` subpaths); the renderers ship one file per module with only CSS marked as side effects, so a host that imports `useAlfakitNavigation`, `Icon` and the header components from the package root bundles only those (the panel runtime loads with `Alfakit/Page`).

## Plugins

`php artisan make:alfakit-plugin Blog --vendor=acme [--frontend=react|vue|svelte]` creates `packages/blog`: `BlogPlugin implements AlfaSix\Alfakit\Contracts\Plugin` (`make()`, `getId()`, `register(Panel $panel)`, `boot(Panel $panel)`; add with `$panel->plugin(BlogPlugin::make())`), a service provider and `composer.json`. Plugin CSS/JS go in the panel `<head>` with `AlfaSix\Alfakit\Support\Assets\Assets::register([Css::make('blog', __DIR__.'/../resources/dist/blog.css'), Js::make('blog', $path)->module()], package: 'acme/blog')` (optionally `panel: 'admin'`); local files are published by `php artisan alfakit:assets` (run by `alfakit:upgrade`, which `alfakit:install` adds to composer's `post-autoload-dump`). `->loadedOnRequest()` keeps one out of `<head>`: send `Assets::getStyleHref('id', 'acme/blog')` / `getScriptSrc()` in the component's `getSchemaProps()` and call `loadStyle(href)` / `loadScript(src)` from `@alfakit/core` in the component. `Js::make('analytics')->html('<script>…</script>')` renders an inline script (no path; `<script>` tags get the CSP nonce). `Assets::registerCssVariables(['blog-accent' => '#f50'], package: 'acme/blog')` sets `:root` variables; `Assets::registerScriptData(['blog' => [...]])` fills `window.alfakitData` (`getScriptData('blog')` in `@alfakit/core`). Renderer components are exported by the plugin's frontend package and spread into `createAlfakit({ components })`.

Declare compatibility in the plugin's `composer.json` under `extra.alfakit`: `{"version": "^1.0", "frontend": "@acme/blog"}` (`version` is a Composer constraint on `alfasix/alfakit`; `frontend` is the optional npm package and must be in the app's `package.json` at the plugin's major). `php artisan alfakit:upgrade` reports every installed plugin and `@alfakit/*` npm package as compatible / incompatible / unknown against the installed version and only fails with `--strict`. Report deprecated APIs with `AlfaSix\Alfakit\Support\Deprecations::warn('Table::actions()', 'use recordActions() instead', since: '1.2')` (logged once per process; `Deprecations::all()` / `toDebug()` list them, `flush()` resets). Every page shares `alfakit.schemaContract` (`AlfaSix\Alfakit\Support\SchemaContract::VERSION`); renderers show a translated message instead of the page when its major differs from `SCHEMA_CONTRACT_VERSION` in `@alfakit/core`.

## Notifications

```php
Notification::make()->title(__('Saved'))->body(__('Your changes were saved.'))->success()->send();
Notification::make()->title('Export ready')->sendToDatabase($user); // needs ->databaseNotifications() on the panel
Notification::make()->title('Deployed')->success()->broadcast($user); // live toast; needs ->realtime() (or ->realtimeNotifications()) and Laravel Echo
Notification::make()->title('New comment')->sendToDatabase($user, isEventDispatched: true); // also refreshes open bells live
```

Database notification actions: `Action::make('unread')->markAsUnread()` (`AlfaSix\Alfakit\Notifications\Actions\Action`; also `->color()`, `->icon()`, `->size(Size::Small)`, `->button()`/`->link()`). `Notification::make()->color('success')` tints the toast/bell background (`status()` still picks the icon), `->date($iso)` sets the bell date. Show a toast from JS with `showToast({ id, title, status, format: 'alfakit' })` from `@alfakit/react|vue|svelte`. Tests outside page tests: `Notification::fake()` then `Notification::assertNotified('Saved')` / `assertNotNotified()` (without the fake they read the session flash). Custom Laravel notifications return `Notification::make()->title('Paid')->getDatabaseMessage()` from `toDatabase()` and `->getBroadcastMessage()` from `toBroadcast()`. Open the bell panel with a page action `->openDatabaseNotifications()` or `openDatabaseNotifications()` from `@alfakit/core`. Close a toast by id with `closeNotification('greeting')` from `@alfakit/core` (ids: `Notification::make('greeting')` or `$notification->getId()`; from PHP a notification action can `->dispatch('alfakit:close-notification', ['id' => 'greeting'])`). Put the bell in the sidebar with `->databaseNotifications(position: DatabaseNotificationsPosition::Sidebar)` (`AlfaSix\Alfakit\Support\Enums`; also `->databaseNotificationsPosition('sidebar')`); `topbar(false)` moves it there by default. Renderers show `<NotificationsMenu variant="sidebar">` in the sidebar when `panel.databaseNotifications.position === 'sidebar'`.

Toast placement: `->toastPosition(ToastPosition::BottomEnd)` (`AlfaSix\Alfakit\Support\Enums\ToastPosition`; `start`/`end` follow the reading direction).

## Emails

AlfaKit's and its plugins' emails share a branded theme (default panel's brand name, logo, primary colour, font; `dir`/`lang` from the locale the mail is rendered in; dark variant; CSS inlined). Options in `config('alfakit.mail')`: `theme`, `verify_email`, `panel`, `name`, `logo` (PNG; SVG panel logos are skipped), `dark_logo`, `logo_height`, `primary_color`, `font`, `url`. Put your own mails in the theme:

```php
use AlfaSix\Alfakit\Mail\MailMessage; // notifications: instead of Laravel's MailMessage
return (new MailMessage)->subject('Export ready')->line('Download it within 24 hours.')->action('Download', $url);

use AlfaSix\Alfakit\Mail\Concerns\UsesAlfakitMailTheme; // Mailables with new Content(markdown: ...)
```

Preview page: `$panel->pages([\AlfaSix\Alfakit\Pages\MailPreview::class])` (local/debug, the `viewAlfakitMailPreview` gate, or `MailPreview::authorize(fn (User $user): bool => ...)`) renders every registered mail light/dark and LTR/RTL. Register mails (preview with unsaved models) and make them editable by admins (`alfasix/alfakit-mail-templates`):

```php
use AlfaSix\Alfakit\Mail\{EditableTemplates, MailDefinition, Mails};
use AlfaSix\Alfakit\Mail\Concerns\UsesEditableTemplate;

Mails::register(MailDefinition::make('orders.shipped')->label(fn () => __('Order shipped'))->group(fn () => __('Orders'))
    ->preview(fn () => new OrderShipped(Order::factory()->make()))
    ->editable(mergeTags: ['name' => 'Customer', 'button' => 'Track button'], subject: 'Order {{ name }}', body: fn () => MailDefinition::paragraphs('Hi {{ name }},', '{{ button }}')));

class OrderShipped extends Mailable { use UsesAlfakitMailTheme, UsesEditableTemplate;
    public function envelope(): Envelope { return new Envelope(subject: $this->templateSubject('Order shipped')); }
    public function content(): Content { return $this->templateContent(new Content(markdown: 'mail.shipped')); }
    public function templateKey(): string { return 'orders.shipped'; }
    public function templateData(): array { return ['name' => $this->order->customer_name, 'button' => EditableTemplates::button($url, 'Track')]; }
}
// Notifications: return $this->templateMailMessage((new MailMessage)->...);
```

Merge tag values are escaped unless `Htmlable` (`EditableTemplates::button()` / `link()`); templates apply per locale only. `MailTheme::render($view, $data)` / `renderText()`, `MailTheme::brandUsing(fn (?Panel $panel) => new MailBrand(...))`, `MailPreview::renderMail(Mails::get($key), 'ar')` in tests. Publish views with `--tag=alfakit-mail`.

## Real-time collaboration

`$panel->realtime()` (off by default; `bool|Closure`, optional `connection:`; also `->broadcastConnection('reverb')`) turns on, over Laravel broadcasting + Echo: presence avatars on View/Edit pages ("Dana is editing"), a non-blocking conflict banner on Edit pages when someone else saves (review the changed fields vs your unsaved values, reload, keep mine), live tables/widgets and instant bell refreshes for stored database notifications. While off nothing is registered. Set up with `php artisan alfakit:realtime`, then `php artisan reverb:start` and a queue worker.

```php
$panel->realtime()->broadcastModelChanges(); // resource models are observed automatically (keys only are broadcast)
$table->live(); // alias liveUpdates(debounce: 500, newRecordsIndicator: true, fallbackPollingInterval: '30s', models: [Post::class])
StatsOverview::make()->live([Order::class]); // widgets; or protected bool|Closure $hasLiveUpdates = true; protected array|Closure|null $liveModels = [...]
class Comment extends Model { use \AlfaSix\Alfakit\Realtime\BroadcastsToAlfakit; } // models without a resource
```

- Channels (authorised by AlfaKit with the panel guard, panel access, tenant membership and policies): `private-alfakit.{panel}.{tenant}.{Model-Class}` (`viewAny`) and `presence-alfakit.{panel}.{tenant}.{Model-Class}.{key}` (`view` or `update` on the record via the resource's tenant-scoped query); `{tenant}` is the tenant key or `_`. Echo authenticates at `/{panel}/_alfakit/broadcasting/auth`.
- Changes dispatch `AlfaSix\Alfakit\Realtime\RecordChanged` after commit with `{event, model, key, by, at}` only, never attributes; skip some with `shouldBroadcastToAlfakit(string $event): bool` on the model. Test with `Event::fake([RecordChanged::class])`.
- Optimistic concurrency works without realtime: Edit pages send the loaded record version (`recordVersion`, a keyed hash of the row) and a stale save is refused (error notification + banner, validation key `alfakitConflict`). On by default; `->detectConflicts(false)` on the panel or `protected static ?bool $detectsConflicts = false;` on an `EditRecord` page. Code calling `$page->save($data)` isn't checked.
- Frontend: Echo comes from `window.Echo`, `createAlfakit({ echo: (options) => new Echo({ ...options, broadcaster: 'reverb', Pusher }) })`, or `config('alfakit.broadcasting.echo')` (public options; `laravel-echo`/`pusher-js` are optional peers loaded dynamically). Without Echo, live tables/widgets poll at `fallbackPollingInterval`.

## Installable app (PWA) and Web Push

`$panel->pwa()` (off by default) adds a web app manifest (`/{path}/manifest.webmanifest`, name/short_name from the brand, `theme_color` from `primary`, `lang`/`dir` from the locale, start_url/scope = panel path), a dependency-free service worker (`/{path}/sw.js` with `Service-Worker-Allowed`: precaches the panel's Vite entries, cache-first build assets, network-first pages that are never stored, offline page `/{path}/offline`, never caches `/_alfakit/*`), head tags (manifest, light/dark `theme-color`, `apple-touch-icon`), an "Install app" item in the user menu and command palette (iOS Safari: "Add to Home Screen" hint) and a "A new version is available — Reload" toast after deploys.

```php
$panel->pwa(
    icons: ['192x192' => '/icons/icon-192.png', '512x512' => '/icons/icon-512.png', ['src' => '/icons/maskable.png', 'sizes' => '512x512', 'purpose' => 'maskable']],
    push: true,                    // Web Push for database notifications
    name: 'Acme', shortName: 'Acme', description: null,
    themeColor: '#0f766e', darkThemeColor: '#042f2e', backgroundColor: '#ffffff',
    manifest: ['categories' => ['business']], // extra members, merged last
);
```

- Without `icons:` an SVG favicon/logo is listed as-is and 192/512/maskable PNGs are generated (GD) from a raster favicon/logo in `public/` or the brand initial.
- Push setup: `php artisan alfakit:pwa-keys` (writes `ALFAKIT_PWA_VAPID_PUBLIC_KEY`/`_PRIVATE_KEY` to `.env`; `--show`, `--force`), set `ALFAKIT_PWA_VAPID_SUBJECT`, `php artisan vendor:publish --tag=alfakit-pwa-migrations && php artisan migrate` (table `alfakit_push_subscriptions`). No composer package needed (OpenSSL encryption + VAPID). Every `Notification::make()->sendToDatabase($user)` is also pushed to the user's subscribed browsers (title, plain-text body, first action URL); push anything else with `AlfaSix\Alfakit\Pwa\PushNotifications::send($user, ['title' => '…', 'body' => '…', 'url' => '/admin/…'])`.
- Custom root views: add `{{ $alfakitPanel->renderPwaHeadTags() }}` to `<head>`. Frontend: `pwaStore`, `promptPwaInstall()`, `applyPwaUpdate()`, `subscribeToPush()`, `unsubscribeFromPush()` from `@alfakit/core`; menu items carry `data-slot="pwa-install"` / `"pwa-push"`; the offline page is the `alfakit::pwa.offline` view.

## Debugging

- `php artisan alfakit:doctor` checks the installation (versions, renderer package and version match, Vite manifest, SSR, panels/resources/policies, translation overrides, storage:link, queue, broadcasting for `->realtime()`, APP_KEY, debug in production, migrations of opted-in features, caches) and prints fixes; `--json` for CI, `--strict` fails on warnings. Run it first when something does not render or a feature silently does nothing. Packages add checks with `Doctor::extend(fn () => [DoctorCheck::ok('Group', 'Label', 'message')])`.
- `$panel->devTools()` (default: on in `local`, never unless `app.debug` is on) adds a floating schema inspector: the page props as a searchable JSON tree with copy, what the context token identifies (panel, page, route parameters, expiry; never secrets), the `Server-Timing` server time, payload size and editor links for the page/resource/model classes (`APP_EDITOR`). Replace it with the `panel:dev-tools` registry key.
- `$panel->debugPanel()` (default: on in `local`, and never unless `app.debug` is on) adds a bug icon to the top bar. The drawer shows the page's resolved schema tree with visibility and authorisation per component and the reason a node is hidden, the live form state, every internal request with server time (`Server-Timing`) and sizes, query count, memory and the closures that ran (owner, file, line, count). Nothing is sent in production.
- In tests, `alfakit()->testPage(EditPost::class, ['record' => $post])->dump()` prints the same tree (`->dd()` stops; `->getDebugTree()` returns the array) without enabling the panel.

## Pitfalls

- Never import `Filament\...` classes; the API is similar, but the namespaces are `AlfaSix\Alfakit\...`.
- Classes and pages live in the panel's discovery directories; run `php artisan alfakit:optimize-clear` if a new one doesn't show up.
- Don't build JavaScript for things PHP can express. Custom frontend code is only for new visual components. See the `alfakit-frontend-components` skill.
- Notification bodies, modal descriptions, helper text and hints escape plain strings. Wrap trusted markup in `new HtmlString(...)`.
- `->html()` / `->markdown()` on `TextColumn`/`TextEntry`, string content of `Html::make()` and `RichContentRenderer` are sanitised on the server (Symfony HtmlSanitizer); an `Htmlable` from code is trusted. Opt out only for trusted content: `->html(sanitize: false)`, `Html::make($s)->sanitize(false)`, `RichContentRenderer::make($c)->sanitize(false)`. Widen the allowlist per panel with `->htmlSanitizer(fn (HtmlSanitizerConfig $config) => $config->allowElement('iframe', ['src']))`; sanitise your own output with `AlfaSix\Alfakit\Support\Html::sanitize($html)`.
- `url()` on columns, entries, actions, navigation/menu items, notification actions and stats keeps only http(s), mailto, tel and relative URLs (`javascript:` etc. become no link). Use `AlfaSix\Alfakit\Support\Url::sanitize($url)` for URLs you output yourself.
- `ColorColumn` / `ColorEntry` only send plain CSS colours (hex, `rgb()`/`hsl()`/`oklch()`… with numbers, keywords); sanitise colours you inline yourself with `Str::sanitizeCssColor($c)` (null when unsafe). Fluent versions: `str($html)->sanitizeHtml()`, `str($url)->sanitizeUrl()`, `str($c)->sanitizeCssColor()`.
- Relationship options, `unique()` and `exists()` are scoped to the current tenant automatically; use `AlfaSix\Alfakit\Support\TenantScope::apply($query)` for your own queries in tenant panels.
- In tenant panels, implement `AlfaSix\Alfakit\Contracts\HasDefaultTenant` on the user to choose which tenant the panel root and login redirect to (it must be a tenant the user can access; otherwise the first tenant is used).
- Relation managers are read-only on View pages; override `isReadOnly()` to change that.
- `->tenantRegistration(RegisterTeam::class)` and `->tenantProfile(EditTeamProfile::class)` need your own concrete subclass of `RegisterTenant` / `EditTenantProfile`; the base classes are abstract and are rejected with an `InvalidArgumentException`.
